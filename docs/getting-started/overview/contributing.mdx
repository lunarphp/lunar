Lunar accepts contributions as GitHub issues and discussions, and the Lunar team implements accepted changes.

## How Contributions Work

Pull requests to the [lunarphp/lunar](https://github.com/lunarphp/lunar) monorepo are limited to collaborators. Pull requests from outside the Lunar team are not accepted.

Instead, contributors report bugs as issues and propose features in discussions. The Lunar team, working with Claude, turns accepted reports and proposals into code, tests, and documentation. A clear, well-evidenced issue or discussion is the most useful contribution to the project.

| Contribution | Where it goes |
| --- | --- |
| Bug report | A [new issue](https://github.com/lunarphp/lunar/issues/new/choose) using the bug form |
| Feature request or enhancement | [Discussions](https://github.com/lunarphp/lunar/discussions/new/choose) |
| Documentation correction | A [new issue](https://github.com/lunarphp/lunar/issues/new/choose) naming the page and what is wrong or missing |
| Usage question or support | [Discussions](https://github.com/lunarphp/lunar/discussions/new/choose) or [Discord](https://lunarphp.com/discord) |

<Warning>
Security vulnerabilities should not be reported as public issues. See the [Security](/getting-started/overview/security) page for responsible disclosure instructions.
</Warning>

## Reporting a Bug

Open an issue on [lunarphp/lunar](https://github.com/lunarphp/lunar/issues/new/choose) using the bug form. The form asks for:

- The affected release lines (`1.x`, `2.x`, or both)
- The exact Lunar, PHP, and Laravel versions, and the database driver
- The expected behavior and the actual behavior
- Minimal steps to reproduce the problem from a fresh install

Reports without reproduction steps usually cannot be actioned and are closed after two weeks without a response.

A report is resolved faster when it also includes:

- The full error message and stack trace
- A failing Pest test, pasted into the issue as a code block, that uses the monorepo's existing factories
- A link to the file and lines on GitHub where the problem appears to be, if it has been traced

<Tip>
To write a failing test, set up the monorepo locally by following the [Local Development](/getting-started/overview/local-development) guide.
</Tip>

Creating an issue does not guarantee immediate activity. The Lunar team reviews issues as time allows.

## Proposing a Feature

Start a [discussion](https://github.com/lunarphp/lunar/discussions/new/choose) for any new feature or enhancement. Describe the problem the feature solves, not only the proposed solution: how the store works today, what is missing, and what has been tried.

A prototype on a branch of a personal fork can help illustrate a proposal. Link to it from the discussion; it is used as context and is not merged as-is. If the Lunar team accepts the proposal, the team implements it.

## Documentation

Lunar's documentation is built with [Mintlify](https://mintlify.com/) and written in MDX. The 1.x docs live in the `docs/` directory on the `1.x` branch of the [monorepo](https://github.com/lunarphp/lunar/tree/1.x/docs), next to the code they describe, and publish to docs.lunarphp.com with each 1.x release.

To report a mistake, an outdated example, or a missing topic, open an [issue](https://github.com/lunarphp/lunar/issues/new/choose) that links to the page and describes the problem. Suggestions for new guides or larger restructuring belong in [Discussions](https://github.com/lunarphp/lunar/discussions/new/choose).

The Support, Flight Plan and v0 pages are maintained by the Lunar team. Suggest changes to them in [Discussions](https://github.com/lunarphp/lunar/discussions).
